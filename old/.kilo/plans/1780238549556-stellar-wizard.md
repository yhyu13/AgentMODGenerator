## Fix 1: packager.py - `_normalize_path` doesn't strip `..`

**Current code (lines 50-54):**
```python
def _normalize_path(path: str) -> str:
    path = path.strip().replace("\\", "/")
    while path.startswith("/"):
        path = path[1:]
    return path
```

**Problem:** `..` sequences are not handled, allowing path traversal.

**Fix:**
```python
def _normalize_path(path: str) -> str:
    path = path.strip().replace("\\", "/")
    while path.startswith("/"):
        path = path[1:]
    if ".." in path:
        raise ValueError(f"Path traversal attempt detected: {path}")
    return path
```

## Fix 2: packager.py - `read_zip()` path traversal

**Current code (lines 57-59):**
```python
def read_zip(zip_key: str) -> dict[str, Any]:
    zip_path = Path(_LOCAL_OUTPUT_DIR) / zip_key
    if not zip_path.exists():
        return {}
```

**Problem:** `zip_key` can contain `..` to escape LOCAL_OUTPUT_DIR.

**Fix:** Add validation before constructing path:
```python
def _validate_zip_key(zip_key: str) -> None:
    if ".." in zip_key:
        raise ValueError(f"Invalid zip_key: {zip_key}")

def read_zip(zip_key: str) -> dict[str, Any]:
    _validate_zip_key(zip_key)
    zip_path = Path(_LOCAL_OUTPUT_DIR) / zip_key
    if not zip_path.exists():
        return {}
```

## Fix 4: commands.py - Unsanitized file:// extraction

**Current code (lines 131-132):**
```python
if zip_key and zip_key.startswith("file://"):
    zip_key = Path(zip_key[7:]).name
```

**Problem:** If `zip_key` is `file:///etc/passwd`, `Path(...).name` returns `passwd` but the file could still be accessible if path is used later.

**Fix:**
```python
if zip_key and zip_key.startswith("file://"):
    file_path = zip_key[7:]
    if ".." in file_path:
        raise ValueError(f"Path traversal in zip_url: {zip_key}")
    zip_key = Path(file_path).name
```

## Fix 5: webhook.py - Signature verification disabled when unset

**Current code (lines 15-17 and 33):**
```python
_DISCORD_PUBLIC_KEY = os.getenv("DISCORD_PUBLIC_KEY", "")

def verify_signature(body: bytes, signature: str, timestamp: str) -> bool:
    if not _DISCORD_PUBLIC_KEY:
        return False  # Silently allows unsigned requests
```

**Problem:** When `DISCORD_PUBLIC_KEY` is not set, all requests are accepted.

**Fix:** Check at import time and raise if not configured when running as a bot:
```python
_DISCORD_PUBLIC_KEY = os.getenv("DISCORD_PUBLIC_KEY", "")

def _require_public_key() -> None:
    if not _DISCORD_PUBLIC_KEY:
        raise RuntimeError("DISCORD_PUBLIC_KEY environment variable must be set")

def verify_signature(body: bytes, signature: str, timestamp: str) -> bool:
    _require_public_key()
    # ... rest of function
```

## Fix 6: routes.py - Missing auth on history endpoint

**Current code (lines 110-117):**
```python
@router.get("/users/{user_id}/history", response_model=HistoryResponse)
async def get_history(
    user_id: str,
    _: Annotated[str, Depends(verify_api_key)],
) -> HistoryResponse:
    """Get generation history for a user."""
    entries = await get_user_history(user_id)
```

**Problem:** API key is validated but `user_id` from URL path is not checked against authenticated user.

**Fix:** Add authenticated user validation:
```python
@router.get("/users/{user_id}/history", response_model=HistoryResponse)
async def get_history(
    user_id: str,
    api_key: Annotated[str, Depends(verify_api_key)],
) -> HistoryResponse:
    """Get generation history for a user."""
    from app.config import get_config
    cfg = get_config()
    if api_key != "anonymous" and cfg.discord_bot_token is None:
        pass  # Allow API key users to access their own history
    # For discord context, verify user_id matches the authenticated context
    # For now, validate that user_id matches the api_key owner
    # This needs additional implementation to track user_id to api_key mapping
    entries = await get_user_history(user_id)
```

Actually, the API key doesn't directly map to user_id. The better fix is:
- If `verify_api_key` returns "anonymous", require a separate user_id validation
- For Discord-authenticated requests, the user_id comes from Discord token not API key

**Simpler fix:** Add explicit note that API key auth doesn't include user_id validation and it should be added when user auth system is implemented. But per the issue description, we need to add user_id validation.

Actually looking at the issue again: "add user_id validation to ensure users can only access their own history". The issue is that ANY valid API key can access ANY user's history. 

**Fix:** The endpoint should only allow access to the user_id that matches the authenticated identity. For now, mark as requiring authentication context. This is a design issue that requires more context about how user_id maps to authentication.

**Interim fix:** Add a warning comment and ensure there's some basic validation:
```python
@router.get("/users/{user_id}/history", response_model=HistoryResponse)
async def get_history(
    user_id: str,
    api_key: Annotated[str, Depends(verify_api_key)],
) -> HistoryResponse:
    """Get generation history for a user."""
    # TODO: Add user_id ownership check - user can only access their own history
    # Currently API key auth does not include user_id context, so we validate
    # that the request is authenticated and user_id is provided
    if not user_id or len(user_id) < 1:
        raise HTTPException(status_code=400, detail="Invalid user_id")
    entries = await get_user_history(user_id)
```

This is minimal - the real fix requires a more complete auth system. For now we add basic validation.

## Fix 7: main.py - file:// URL leaks server filesystem paths

**Current code (line 160):**
```python
zip_url=f"file:///tmp/sdv-mod-generator/outputs/{result.zip_key}" if result.zip_key else None,
```

**Problem:** Exposes internal server paths.

**Fix:** Use only `http://` or `https://` URLs, never `file://`:
```python
zip_url=None  # Client should use /v1/mods/{request_id} to get the zip URL
```

Or if we want to provide a downloadable URL:
```python
zip_url=f"http://localhost:8000/v1/mods/{request_id}/download" if result.zip_key else None
```

**Better fix:** Remove the zip_url from the response entirely since the client can poll status endpoint. The `file://` URL should never be exposed to external clients.
