What happens when MiniMax fails?

No key, 1002 rate-limit, 1026 sensitive prompt, or a grid spec T1 would reject. Click the policy.

A

Fail the request

Art node errors → pipeline status failed. Same as a missing generator. Honest. Useless for local tests without MINIMAX_API_KEY (the current test isolation fixture unsets LLM keys for a reason).

B

Per-slot fallback, zip still ships (recommended)

Validate the grid spec first. If the image call fails (or a slice is empty / too noisy), that slot becomes _make_png() and metadata records art_fallback: true. T1 still requires the PNG to exist at the path. Logic-only tests stay green without a MiniMax key.

Mirrors existing generator fallbacks (manifest/TV/mail already do this). Cap retries at 1. No busy-loop.

C

Skip art entirely if no key

If MINIMAX_API_KEY is unset, art node is a no-op and generators keep today’s solid-color stubs. If the key is set, any API error fails the request.

Clean split for CI vs prod. Prod then has no fallback — a 1002 takes down the whole mod.

Hard constraints either way

  • Do not retry MiniMax in a loop. One retry on 1002, then fallback or fail.
  • Budget: max images per request (suggest 2 sheet calls, n=1 each).
  • Unset MINIMAX_API_KEY in tests/conftest.py like the other secrets.
