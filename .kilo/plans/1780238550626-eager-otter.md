# Fix Generator and Pipeline Issues — Plan

## Issue 1: `gate_t1.py:62-67` — Inverted JSON validation logic

**Problem**: The `_validate_file` function (lines 62-67) silently passes invalid strings because the condition logic is inverted.

**Current code**:
```python
if file_path.endswith(".json"):
    if not isinstance(content, dict):
        try:
            json.loads(content) if isinstance(content, str) else None
        except Exception:
            errors.append(f"{gen_name}: {file_path} is not a JSON object")
```

**Fix**: When content is not a dict AND not a valid JSON string, it should add an error. The `try/except` should only be entered when content is a string (JSON string). The condition should be inverted:

```python
if file_path.endswith(".json"):
    if not isinstance(content, dict):
        if isinstance(content, str):
            try:
                json.loads(content)
            except Exception:
                errors.append(f"{gen_name}: {file_path} is not a JSON object")
        else:
            errors.append(f"{gen_name}: {file_path} is not a JSON object")
```

## Issue 2: `pipeline.py:56-61` — Generator-not-found errors swallowed

**Problem**: When a generator is not found, the code logs a warning, appends to errors, then `continue` — so other generators still run, but the status is never set to "failed". The loop continues and if any generator produces output, the pipeline continues to packaging marked "done".

**Current code** (lines 56-61):
```python
for gen_name in state.generators:
    gen_cls = pack.get_generator(gen_name, state.phase)
    if gen_cls is None:
        logger.warning("pipeline.generator_not_found", ...)
        state.errors.append(f"Generator not found: {gen_name}")
        continue
```

**Fix**: Remove the `continue` so the loop proceeds but doesn't add invalid output. Actually, the error IS being appended. The real issue is that after the loop, the code checks `if not state.outputs and state.errors` — but since the generator wasn't found (no generate() call), there's no output for that generator. The logic should NOT mark as "done" if any generator was not found.

The fix: when a generator is not found, the code should still append to errors and prevent marking as done. The current issue is the loop continues but doesn't track that this is a critical failure. Actually looking more carefully — the `continue` skips adding output, so `state.outputs[gen_name]` is never set. If ALL generators are not found, `state.outputs` stays empty and `state.errors` has content, so `state.status = "failed"` gets set at lines 83-86. But if SOME generators succeed and some are not found, the pipeline still marks as "done" in `node_package` (line 144).

**Fix**: Change `continue` to `return state` with status="failed" OR set status to failed immediately when a required generator is not found:

```python
if gen_cls is None:
    logger.error("pipeline.generator_not_found", request_id=state.request_id, generator=gen_name, game=state.game)
    state.errors.append(f"Generator not found: {gen_name}")
    state.status = "failed"
    return state  # Abort early
```

## Issue 3: `shop_channel/__init__.py` — Bare `except Exception` at 9+ locations

**Problem**: Multiple bare `except Exception` clauses silently catch errors and return fallbacks. While they log, they silently use potentially bad data.

**Locations**: Lines 93, 135, 197, 243, 285, 366, 411, 453, 497

**Fix**: For each location:
1. Catch specific exceptions (`json.JSONDecodeError`, `ValidationError`, `AttributeError`, `IOError`, `RuntimeError`, etc.)
2. Keep the logger.error() call
3. Keep the fallback behavior

Example (line 93):
```python
# Before
except Exception:
    return ["Parsnip Seeds", ...]

# After
except (ImportError, AttributeError, KeyError) as exc:
    logger.warning("get_sdv_item_names.fallback", error=str(exc))
    return ["Parsnip Seeds", ...]
```

For LLM generation failures, catch `ValueError`, `RuntimeError`, `json.JSONDecodeError` (from parse failures), etc.

## Issue 4: `texture/__init__.py` — Bare `except` at line 66

**Problem**: Same issue — bare `except` silently catches all errors including KeyboardInterrupt, SystemExit, etc.

**Fix**: Change to `except Exception` to match shop_channel pattern, or better yet, specific exceptions. Since this is LLM-generated content, catch `ValueError`, `RuntimeError`, `IOError`, and `json.JSONDecodeError`:

```python
except (ValueError, RuntimeError, IOError, Exception) as exc:
    logger.error("texture_generator.failed", error=str(exc))
    # fallback...
```

Actually `Exception` is fine here as a fallback but should be more specific. Let's use `(ValueError, RuntimeError, IOError)` since those cover the likely failures.
