# 让 LLM 写星露谷模组，不要让模型硬写全部文件

**TL;DR**

- 别让一个大模型硬写全部文件。常见需求走模板，新句子才交给 LLM。
- 形状是游戏认的数据长什么样，不是「JSON 能解析」。
- 教模型和检查模型必须用同一张说明书。过门才打包。
- 「我写好了」不算完。听游戏日志里改了哪张表。
- 能抄走的是这套切割，不是某个仓库里的文件名。

给 Agent 加「一句话生成模组」，第一反应通常是三件事：提示词丢进一个万能模型、吐出整棵目录就打包、JSON 能解析就算完成。

这三条都快，也都会在同一处裂开：游戏根本不认这份字段；半成品 zip 进了玩家文件夹；模型把「看起来合理」当成「能进游戏」。

我们没改成万能作者。贯穿始终的一句话是：

**形状是真相，过门才打包。**

人话就是：先弄清游戏吃什么样的补丁；说明书和检查用同一套；过关才给 zip；游戏日志里真的改了表，才叫做成了。下面按这个顺序讲。每一步先说它是什么，再说它不是什么。

---

## 第一反应是错路

别把「生成模组」焊成一次大模型调用。发动机是流水线；模型只写模板覆盖不了的那一段补丁。

![错路是万能模型整包吐目录；正路是模板保底、对照说明书写补丁、过门才打包](images/05-wrong.png)

是：常见需求走写死的模板；新句子对照游戏数据形状写 Content Patcher 补丁；门按同一套形状检查；过关才打 zip。

不是：一个模型硬写全部文件，也不是提示词里写「请生成正确模组」，更不是 JSON 合法就算完成。

---

## 脉络：一句话出包，不要万能模型

判断按这条链往下走。上一步如果走了「不是什么」，后面的实现再漂亮也会裂。

![需求 → 接缝 → 树根 → 主干 → 切开。主线：形状是真相，过门才打包](images/06-thread.png)

| 步 | 是什么 | 不是什么 |
|---|---|---|
| 需求 | 一句中文，拿到能丢进游戏的包 | 改游戏程序；万能模型吐整棵目录 |
| 接缝 | 常见走模板，新概念走作者；谁也不私藏形状 | 一个模型既当老师又当门 |
| 树根 | 游戏认的数据长什么样 | 生成器自己的 JSON 风格 |
| 主干 | 说明书和检查同一套，过关才打包 | 模型写完就打 zip |
| 切开 | 出包、写新句子、放行、挂上，四问分开 | 四问并成一次模型调用 |

## 先把词落地

后文每根枝都用这些词。不先钉死，树会变成黑话。

星露谷本体不读你丢进文件夹里的随便一个 zip。中间隔着两层。

**SMAPI** 是模组加载器。游戏启动时由它扫描 `Mods/`，把模组挂上去，并把过程写进日志。没有它，后面的包进不去。

**Content Patcher** 挂在 SMAPI 上。它不改游戏程序，只补丁数据表：物品、鱼、配方、对话。它认的包很瘦：一份名单（这是谁）加上一份补丁清单（改哪张表、改成什么样）。

所以玩家拿到的 zip，不是「一段看起来像模组的文本」，而是 Content Patcher 吃得下的补丁。日志里出现「改了物品表」，才叫挂上。

生成器这一侧三个词。

**说明书**（仓库里那份数据形状文件）告诉作者：每种表在 1.6 里长什么样。机器必须带一种特殊前缀，并且旁边还要有一个能放下来的家具条目。配方原料写数字编号，不写「石头」「铜矿石」。它不是提示词里一句「请生成正确模组」，而是可检查的形状。

**模板 / 通用作者** 对照说明书写出补丁。常见需求走模板；鱼、机器、遗物这类新句子走 LLM。

**T1** 是第一道门。不调模型，不看漂不漂亮，只拿说明书核对这份补丁。过了才打 zip。过不了，半成品不进玩家手里。

![左边是游戏怎么把 zip 挂上去；右边是生成器怎么对照说明书写出、再过门](images/00-terms.png)

后文说「老师」，指说明书。说「门」，指 T1。说「挂上」，指日志里出现对应的表。

## 整棵树

这件事不是一个开关，而是从游戏数据长出来的一棵树。

- **树根**：游戏吃得下的补丁形状，才算模组
- **主干**：老师教形状，门卡同一套，过关才打 zip
- **四根分支**：模板、通用作者、门、真机证据
- **树叶**：十份常见需求的包，三份新句子的包，都已经在真机挂上

![从树根长到树叶：游戏形状 → 过门才打包 → 模板 / 作者 / 门 / 真机](images/01-tree.png)

为什么切成树，而不是「提示词 → 模型 → zip」一条直线？因为这四件事回答的问题不一样。混在一起，模型会既当老师又当门，完成标准会漂成「文件能打开」。

是：树根钉死形状；主干保证老师和门同一套；分支各管一问；树叶只是证据，可以换。

不是：一次模型调用包办出包、放行、宣告完成。

---

## 是什么，不是什么

这是一句提示词进、一份补丁包出的流水线。聊天软件或网页接口都能下单，轮询取包，丢进模组文件夹。对着星露谷 1.6、加载器、Content Patcher 真机加载过。

![左边是实际交付；右边是明确不做](images/02-is-isnt.png)

是：常见需求走模板；新概念对照 1.6 写补丁；过门才打包；日志为证。

不是：改游戏程序的代码模组，也不是自定义动态库。那类需求直接拒绝，不塞垃圾包。也不是模型说「我写好了」。

---

## 树根：游戏吃得下的形状，才是模组

为什么树根必须是游戏数据，不是生成器自己喜欢的字段名？

因为补丁的消费者是游戏，不是我们的流水线。游戏认编号、认官方字段、往列表里追加有固定写法。文件能打开，只证明解析器没哭，不证明湖里能钓到鱼。

是：把 1.6 每种表长什么样写进说明书，让作者和门共用。

不是：在提示词里写「请生成正确模组」，也不是「字段名看起来合理就行」。形状不写进老师、只活在某次对话里，模型每次都会换一种看起来合理的字段。

---

## 主干：老师教形状，门卡同一套

为什么主干是「过门才打 zip」，而不是「模型写完就打包」？

LLM 会复述老师。老师教对的前缀，它就写对的前缀。门如果只查「有没有目标字段」，形状不对的包也会混过去。老师和门各说各话，换更大的模型也救不了。

![老师、作者、门共用一套形状；游戏日志是叶子上的证据](images/03-trunk.png)

是：作者对照说明书写；门对照说明书查；过关才打包。

不是：写包的人同时放行，也不是模型口头「写好了」就算过关。

游戏不是另一套标准。加载器跑的还是树根上的形状。日志里出现物品表、家具表，只是证明主干长到了游戏里。

---

## 分支为什么要拆开

四根枝必须分开，因为每一根回答的问题换了就不能用另一根冒充。

**模板** 回答：购物、贴图、日程这类常见句子，怎么稳定出包？字段写死，不靠模型临场发挥。能装配的就不要交给 LLM。这不是退路，是主干在常见需求上的短路。十份包真机全部加载，是这根枝的叶子。

**通用作者** 回答：模板没有的新句子怎么写？发光鱼、炼金机、风暴遗物。它只写数据补丁，对照树根，过门才打包。不是第二个万能生成器，也不写游戏程序。

**门** 回答：这份补丁能不能打 zip？不调模型。不能让写包的同时放行。

**真机证据** 回答：挂上了没有？标题画面没读到的表，等于没测。完成标准落在日志上，不能落在模型自评上。

把这四问并成一次模型调用，门会变软，模板会膨胀成万能作者，真机会被「文件能打开」代替。拆开，是为了每一问都有一个不能被替换的答案。

---

## 树叶：三句话，三份能挂上的包

叶子会换。树根和主干对了，换一条提示词还是同一棵树。树叶只证明主干已经长进游戏，不是只在仓库里自洽。

![发光鱼追加到山湖、炼金机成对注册、唤雷遗物走官方增益和触发器](images/04-leaves.png)

发光鱼：物品表多一条鲤，鱼数据按官方段数写，山湖刷新是追加不是覆盖。日志出现物品表和地点表。

炼金机：十块石头进、一块金矿石出。能放下来的家具，加上带前缀的机器规则，配方用编号。日志出现家具表和配方表。

唤雷遗物：可合成的遗物、官方增益、暴风雨那天生效、法师多一句台词。Content Patcher 劈不出真闪电，暴风雨加增益是它能做的那一档。

三份过门，三份挂上。发光仍借用原版图案。叶子不必完美，主干必须绿。

---

## 收获和结论

树叶会改名，函数会搬家。能抄走的是下面六句。

![六条可搬走的判断：别硬写全部文件；形状是游戏认的；说明书和门同一套；写包的不能放行；听日志；树根错了叶子会裂](images/07-takeaway.png)

**收获**

1. **别让模型硬写全部文件。** 能写死的用模板；只有新概念才交给 LLM。不是一次调用包办。
2. **形状是游戏认的，不是我们编的。** 消费者是游戏。不是「字段看起来合理」。
3. **说明书和检查必须同一套。** 教什么就卡什么，过关才打包。不是老师和门各说各话。
4. **写包的人不能同时放行。** 门不调模型。不是模型自己给自己打勾。
5. **「我写好了」不算完。** 听游戏日志里改了哪张表。不是文件能打开就算完成。
6. **树根错了，叶子再漂亮也会在同一处裂开。** 万能模型、提示词当说明书、JSON 合法就算完——进游戏会对不上。

**结论**

给 Agent 加「一句话生成模组」，不是让它「记得写出正确文件」，而是让世界有一张游戏认的说明书，并且每一次打包都重新过同一道门。能抄走的是这套切割，不是某个仓库里的文件名。

**PS.** 如果你只带走一句：形状是真相，过门才打包。说明书和检查用同一套；游戏日志里改了表，才叫做成了。

**PPS.** 这和「把模型训得更听话」不是一回事。提示词只能引导该写什么；门才决定能不能打包。更大的模型代替不了同一张说明书。

**PPPS.** 文里的阶段名、文件名都会过时。如果你在自己的系统里让模型硬写全部文件、用提示词当说明书、用「能解析」当完成——出包、放行、进游戏，会在同一处裂开。那才是这篇要拦的事。
