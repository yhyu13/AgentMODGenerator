Who writes the sprite-sheet layout?

You picked sheet-then-slice. The model will not invent a clean grid unless we force one. Click one.

A

Fixed slot catalog (recommended)

A frozen grid per game pack. SDV v1 example:

Row 0: channel icon 32×32 · letter bg · catalog tile
Rows 1–N: item cells 16×16, labeled by the logic generators’ item list

LLM only writes per-cell prompts. Slicing is deterministic. Fail a cell → that slot falls back to _make_png(), the rest still ship.

B

LLM emits the grid

An LLM returns {rows, cols, cell_w, cell_h, slots[]}, then MiniMax draws that. Flexible for later games. The grid is now another LLM output that can be wrong (misaligned cells, wrong sizes). Needs a T1-style spec validator before the image call.

C

Two-pass: style lock, then sheet

Call 1: one hero image as subject_reference (MiniMax image-to-image). Call 2: the fixed grid, same seed + reference. Best style consistency. Extra cost, extra failure mode.
